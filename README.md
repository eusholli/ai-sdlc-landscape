# AI SDLC Landscape

An interactive map of the AI tools that work across the software development lifecycle: the tools
in each of 13 phases, two cross-cutting layers (agent infrastructure and model providers) and the
typed relations between them. Every fact on a tool links to the public page it came from.
Where a vendor does not publish a fact, the site says "Not published".

The site is static Next.js on Vercel. The data is one YAML record per tool in `data/tools/`. The
build turns those records into a single JSON file, which you can download from the site.

## Run it

```bash
pnpm install
pnpm dev        # http://localhost:3000
pnpm check      # build the dataset, type check and tests
pnpm build      # static build: every tool page and per-tool JSON
```

## How the code is laid out

| Path | What is there |
|---|---|
| `data/tools/<id>.yaml` | one source record per tool or model provider: the hand-kept data |
| `data/phases.json`, `data/externals.yaml` | the phases, layers and segments; display names for relation targets |
| `data/landscape.json` | generated by `scripts/build-data.ts`, not committed |
| `scripts/build-data.ts` | checks every record and writes `landscape.json`; runs before dev, build, test and check |
| `scripts/check-links.ts`, `scripts/fetch-logos.ts` | `pnpm data:links` checks every source URL; `pnpm logos` fetches vendor logos |
| `scripts/social.ts` | `pnpm social` draws the LinkedIn and X profile images from the site mark into `.social/` |
| `lib/types.ts`, `lib/data.ts` | typed records and the server-side selectors over the dataset |
| `lib/filters.ts`, `lib/format.ts` | facets, search, URL state and display helpers, safe on the client |
| `components/logo.tsx` | vendor logo with a monogram fallback |
| `app/data/tools/[id]` | one static JSON file per tool, fetched by the tool drawer |
| `docs/design-brief.md` | the design contract |
| `scripts/guard.ts` | fails when a client component imports the dataset |
| `scripts/shots.ts` | `pnpm shots`: screenshots of the main pages in both themes, with checks |
| `components/site-nav.ts` | the navigation: Landscape, Analyze choices, Latest updates and About |

Client components never import `lib/data.ts` or the JSON. Server components pass a slim
projection (`toolsLite()`), and the drawer fetches `/data/tools/<id>.json`. `scripts/guard.ts`
enforces this.

## Changing the UI

The UI is written by hand. The `ui` skill in `.claude/skills/ui/` sets out the loop for a person
or an agent:

```bash
pnpm exec playwright install chromium   # once per machine, for pnpm shots
pnpm dev     # make the change and look at it, light and dark
pnpm shots   # in a second terminal: every main page at phone and desktop width, both themes
pnpm check   # data, types, lint, guard and tests
pnpm build   # the production build, as Vercel runs it
```

`pnpm shots` writes PNGs to `.shots/` and fails on sideways scroll, a console error or a page
that does not answer 200. Read `docs/design-brief.md` before touching a component.

## Updating the data

Each tool is one file, `data/tools/<id>.yaml`. To change a fact, edit its value and add or update
the source that states it:

```yaml
pricing_model: usage (credits)
sources:
  - {field: pricing_model, url: https://kiro.dev/pricing/, retrieved: 2026-10-21}
```

A field with no value is left out, and the site shows "Not published". Then:

1. `pnpm check`. It fails on a value with no source, a source with no `retrieved` date, an unknown
   field or phase, or a relation of an unknown type.
2. `pnpm data:links --changed` checks that the sources you touched still answer.
3. For a new tool, `pnpm logos` fetches its logo into `public/logos/`.
4. Commit. Vercel rebuilds the dataset and redeploys on push.

[CONTRIBUTING.md](CONTRIBUTING.md) has the source rules.

## Requests for change

Spotted a wrong or stale fact, or a missing tool? [Request a change](../../issues/new?template=request.yml)
in plain words, with a link to a public page that shows it. Agents can do the same with
`gh issue create`; [CONTRIBUTING.md](CONTRIBUTING.md#making-a-change) says what to include. The
data is also readable as [/llms.txt](https://aisdlclandscape.org/llms.txt),
[/llms-full.txt](https://aisdlclandscape.org/llms-full.txt) and
[/landscape.json](https://aisdlclandscape.org/landscape.json).
